# 工程决策记录

| 编号 | 决策 | 原因 / 何时复议 |
| --- | --- | --- |
| ADR-001 | 电脑采集，设备展示 | 认证、宿主差异与会话聚合属于电脑；减少设备复杂度 |
| ADR-002 | USB优先，Wi-Fi后续 | 可同时供电，便于逐段排错；佩戴阶段再引入配对 |
| ADR-003 | ESP-IDF 5.5.4 | 与同型号 MotoNav 的实测参考和本机可用工具链对齐 |
| ADR-004 | 客户端主题与角色分离 | 支持不同客户端调用同一模型及自定义provider |
| ADR-005 | 完整快照兼心跳 | 小数据量下更容易从丢包和重连恢复，设备不用重建工具历史 |
| ADR-006 | null、来源、TTL并存 | 未知不能等价零，在线不能等价指标新鲜 |
| ADR-007 | 首版姿态切换+轻动效 | 当前48张均为静态姿态，没有连贯动画；先保证准确和稳定 |
| ADR-008 | 板载 Flash 角色包与内置保底 | 1.75C 没有板载 SD 接口。按固件分区预算选择资源，缺失或校验失败时显示保底图形 |
| ADR-009 | 固件core纯C、无动态分配 | 状态逻辑可独立测试，便于约束边界与移植 |
| ADR-010 | 使用 IDF 公共驱动接口 | 参考同板 BSP 时序，屏幕与触摸分别由本地组件管理，应用只依赖板级接口 |
| ADR-011 | 徽章不承担命令批准 | 触屏信息有限；等待提示只定位宿主确认页面 |
| ADR-012 | 源图不改、授权随包 | 保持来源可追溯；美术授权与代码授权分别记录 |

2026-11-18 准备阶段曾选择 IDF 6.1.1。确认目标为 1.75C 后，驱动移植基线调整为 5.5.4。版本依据与实机验收项见[板卡记录](06-hardware-and-environment.md)。早期关于 Opus 美术变体的选型继续按产品规格执行。
