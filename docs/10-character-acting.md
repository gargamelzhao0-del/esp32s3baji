# 白龙娘的动作设计与圆屏实现

在角色页选“工作中”，留出六秒看她自己开工。她先望向右侧，走过去伸手扣住拉手，分两次发力把滚轮桌拖到位，再绕到桌后坐下。桃色开关被按下之后，折叠显示器才弹起。等她敲起键盘，轻碰显示器，她会用爪子指给你看。也可以打开“口袋 → 小剧场”单独玩搬桌、庆祝和闹别扭。[可玩原型](../design/badge-prototype.html) · [20 秒实录](../design/gpt-pet/desk-story-preview.webp)

## 哪些动画方法适合这枚吧唧

| 一手资料中的方法 | 在圆屏里的取舍和实现 |
| --- | --- |
| 迪士尼角色动画流程重视动作预备、时机、清楚的构图和主动作后的跟随。Lasseter 用传统动画原则解释计算机关键帧中的重量、动作弧线和观众注意力。[迪士尼角色动画流程](https://www.disneyanimation.com/process/animation/) · [SIGGRAPH 原论文](https://users.cs.northwestern.edu/~animation/Lasseter_1987.pdf) | 拉桌前给她一拍看向目标，抓稳再压低重心。桌子起步慢，两次发力中间留一个停顿。跳跃先收翅蹲低，再张翅腾空，落地缓冲之后接一个较小的回弹。小屏上同时保留一个主要动作，把两枚菜单按钮让到上侧。 |
| Kovar、Schreiner 和 Gleicher 描述了脚该着地时随身体平移的滑步问题，并研究了接触开始和结束时怎样平滑过渡。[脚底接触论文与对照片段](https://research.cs.wisc.edu/graphics/Gallery/kovar.vol/Cleanup/) | 本项目按身体走过的距离推进左右脚相位。支撑脚反向抵消身体横移，摆动脚走抬起、跨过、落下的弧线。角色减速时，两脚随路程一起放慢。起步和停步逐渐接入脚步位移。 |
| Spine 的 IK 约束允许用目标点控制手脚，并在约束与原动画之间调节权重。[Spine IK 手册](https://esotericsoftware.com/spine-ik-constraints) | 浏览器里沿用自己的二维网格。先求出画面里手心所在三角形的实际位置，再把误差按手臂权重分给顶点。拖桌时目标是把手，按电源时目标是开关，坐好后目标变成左右键区。手指轮廓单独参与道具遮挡。 |
| Live2D 的物理设置把模型角度和位置作为输入，分别调节反应时间和摆幅。[Cubism 物理设置](https://docs.live2d.com/en/cubism-editor-manual/physics-operation/) | 在现有弹簧上加入拉桌发力的输入。脸先朝向目标，鬓发、头顶发束、流苏以不同速度跟随。尾尖在起跳后才扬起。眼睛和手的响应保持更快，方便立即看懂她在追什么。 |

当前角色由一张透明原画、变形网格、独立眼口和手绘道具连续生成。这样在动作中途仍能找到当下的手心、书角和屏幕。这里借用了接触约束和次级运动的做法，运行依赖是浏览器 Canvas 2D。若要做完整背身、交叉抱臂时露出的袖内侧或大角度绕桌，下一轮美术工作是补画后脑、前后发片和独立袖臂，再用分层骨骼或 Cubism 形变来演。现有原画支持侧身、偏头和收爪的表演。

## 表演、触发与打断

| 表演 | 节拍 | 玩家和 Agent 可以做什么 |
| --- | --- | --- |
| 搬桌开工，约 6.15 秒 | 前 1.6 秒找桌、走近。约 1.8 秒抓稳，随后两次后拉。约 3.9 秒刹住，绕桌勾出凳子。约 5.0 秒按开关，屏幕弹起、点亮并试敲。 | 同一会话连续思考、阅读、写入、执行、搜索、整理会共用桌子。等待确认时立即让出双手，可以点左侧参与工作。手动排练会在坐定办公一会儿后收桌。 |
| 给你看屏幕，约 2.1 秒 | 停手、转屏、指向边框、看一眼你，再把屏幕转回去。 | 轻触坐稳后的显示器，或用“口袋 → 陪她工作 → 看看小屏幕”。阅读用行标，写入用增长的笔迹，搜索用移动的镜片。等待、受限和出错各有图形。屏内笔迹是状态动效，真实额度在下方独立显示。 |
| 大跳庆祝，约 2.9 秒 | 下蹲蓄力、主跳、触地、小跳、单眼招呼。脚跟离开地面时，接触阴影变淡，尾巴和纸花稍晚落下。 | Agent 明确报告成功会触发一次。“本轮结束”和“取消”分别走自己的收工反馈。玩家也能在小剧场邀她欢呼，或在 12 秒内分别成功拍到左右手。 |
| 生闷气，最长约 7.25 秒 | 先收爪，再鼓腮扭身。中间从眼角偷看两次。她会收起被碰的手，过一会儿慢慢转回来。 | 2.65 秒内轻点尾巴三次，或在小剧场选“逗逗尾巴”。这时普通触摸和指针不会把视线拉回。继续戳她也不会延长计时。 |
| 和好，约 2.35 秒 | 从当下的转身角度回头，伸手接糖，视线跟着糖到嘴边，眯眼嚼一下。 | 闹别扭时点“喂星糖”，或在小剧场选“递和好糖”。接到糖时记一次亲密度。 |

Agent 工作、宠物心情、玩家输入各有自己的状态。重复快照不会重播进场或庆祝。界面切换、断开、会话切换或需要用户处理的事件，会取消相关手势和未完成的局部表演。“减少动效”提供坐定、鼓腮、指屏等静态关键姿态，保留触摸、键盘和文字反馈。

## 代码入口

- 时间、走位、动作混合以及打断规则集中在动作控制器。表演使用秒和逻辑画布坐标，玩家输入及 Agent 消息共用这一套时钟。[stage.js](../design/gpt-pet/stage.js)
- 角色网格负责身体重心、脚步、手掌目标和五官局部形变。桌子分为凳子等后景和桌沿等前景，再通过手指轮廓处理遮挡。背景阴影保留在地面。[rig.js](../design/gpt-pet/rig.js) · [face.js](../design/gpt-pet/face.js) · [stage-art.js](../design/gpt-pet/stage-art.js)
- 收到 Agent 事件后由角色控制器决定进入哪一段。击掌、工作玩法和口袋按钮只派发本地输入。新加的回归用例覆盖脚步、连续工具事件、成功判定、和好、双手击掌、指屏和减少动效。[companion.js](../design/gpt-pet/companion.js) · [动作回归测试](../tests/gpt-pet-stage.test.cjs)

## ESP32-S3 上的实现取舍

微雪这款板子是 466 × 466 圆形 AMOLED，CO5300 走 QSPI，CST9217 走 I²C，配有 8 MB PSRAM、16 MB Flash。浏览器当前绘制 612 × 540 的透明缓冲，再缩放到圆屏中央的 340 × 300 区域。上板时应保留动作时序、锚点、层序和输入优先级，重新实现像素绘制。[微雪硬件规格](https://docs.waveshare.net/ESP32-S3-Touch-AMOLED-1.75/)

1. 先移植搬桌这一段。将身体、可动手脚、脸、桌体和折叠屏导出为小图集，在资源中记录掌心、把手、电源键和左右键区。用同一条世界坐标轨迹驱动桌子、手和碰触区域。重复动作通过姿态关键点插值播放。
2. 在板上测 RGB565 分块刷新。两块 466 × 48 的条带合计占 89,472 字节，单个全屏 RGB565 缓冲占 434,312 字节。每帧取旧、新角色和桌子边界的并集，清掉上一帧留下的像素。结合实际驱动的异步完成回调测试画下一块与 QSPI 传输的重叠。[LVGL 9.2 显示缓冲与局部刷新](https://docs.lvgl.io/9.2/porting/display.html)
3. 在实板用同一段表演分别测绘制耗时、传输完成耗时、触摸到反馈延迟和最低可用内存。第一轮可用 24 fps 对应的 41.7 ms 帧预算做对照。若超出预算，优先缓存静态桌体、减小角色重绘范围，再比较局部网格与预渲染身体姿态的成本。手掌接触、眼神和紧急状态提示仍由运行时驱动。

本轮验证覆盖桌面 Chrome、手机宽度触屏模拟、键盘和本机 Agent 测试事件。板端刷新速度、功耗及真实触摸手感留待实板测量。[验证记录](08-validation-log.md)
