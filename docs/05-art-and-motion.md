# 角色素材、动效与资源包

## 当前能直接使用的东西

GPT 网页原型用一张基础立绘制作连续角色动画。眼睑和双翼可以分侧运动。手心、鼻尖、翅膀和尾巴的触点随角色一起运动。击掌由空间命中触发，引萤由距离、速度和停留时间共同触发。手指轮廓控制道具遮挡，落脚阴影随起跳变化。网页还演示了哈欠、睡醒伸展和记住上一次互动的手。下文的 SD 资源格式与预算面向后续设备实现。[动画与署名](../design/gpt-pet/README.md)

现有四位角色各有 12 张透明 WebP 姿态：idle、thinking、reading、writing、running、searching、asking、happy、oops、tired、compact、sleeping。它们是单帧图，不能顺序播放成连贯的运动。文件约 640 px 高，尺寸并不完全一致。

`../assets/character-pack.source.json` 以逻辑状态映射真实文件，包括 Claude 的 `reading-2 / happy-2 / sleeping-2` 文件名。清单明确标注 firmware_ready=false。构建时从清单解析，不能在固件里拼接文件名猜后缀。

首版角色定位：GPT 白龙娘、Claude 铜橙长发持书、DeepSeek 鲸鱼娘、Gemini 星猫娘。Opus / Sonnet 先用 Claude 的型号徽记；独立服装是后续美术任务。仓库包含首版四家族使用的姿态素材；设备端按当前角色加载资源。

## 具体模型如何拥有不同形象

角色选择键是 character_id + variant + pose。首版没有对应变体素材时，明确回退到家族基础角色，同时显示真实型号徽记；不能把一张基础图描述成已经制作好的独立Opus娘。后续资源包可加入variants，不修改Agent接入协议。

以下是本项目的原创美术方向，不是已证实的社区通用设定：

| 变体 | 保留的家族识别 | 建议的独立造型 | 动作重点 |
| --- | --- | --- | --- |
| Claude Opus | 铜橙发、橙花、书 | 深铜色长披肩、金色书页、较庄重的双手持书轮廓 | 慢翻页、思索、展开书页；强调沉稳 |
| Claude Sonnet | 相同发色和橙花 | 较短外套、羽毛笔与便笺、偏浅米色配饰 | 记笔记、轻抬笔、敏捷回应 |
| Claude Haiku | 相同基础脸型与发色 | 轻便斗篷、折纸书签、小纸鸟 | 快速短动作，循环更克制 |
| GPT具体型号 | 白龙角、白发与尾巴 | 先按型号徽记区分；有明确产品定位再设计服饰 | 不把推理强度当成另一模型，不凭版本号臆造性格 |

先制作Opus的idle / thinking / asking / happy四个姿态，再补其余状态。每个姿态沿用基础角色的脸部比例与320px画布锚点。优先通过衣饰轮廓、道具和短标签共同区分，不能只改颜色，否则小屏难辨。变体制作完成后单独做来源、许可、全状态回退与实屏辨识验收。

资源查找顺序：指定变体的指定姿态 → 家族同姿态 → 家族idle → 内置中性角色。缓存键必须包含variant。当前源清单只有家族基础素材，因此对应变体回退是可预期行为。

## 分三步做“活起来”

### A. 首版：姿态 + 轻动效

切换准确的静态姿态，保持统一头部比例、脚底锚点和整体尺度；空闲时上下 1–2 px；工作时细小粒子或图标活动；等用户时慢速提示环；摸头只加短暂小反馈。局部 UI 动效优先，因为整个 320² 人物每帧透明混合的成本高。

不把整张图片强行弯曲当作眨眼，也不把两张生成结果做形变当作稳定连续动作。首版姿态切换可直接切图配 150–250 ms 小幅过渡；双角色全屏交叉淡入需要测带宽后再用。

### B. 可控帧动画

每个常用动作先制作 6–12 个一致帧，建议 10 fps：
- idle：呼吸与眨眼，2–3 s 循环，首尾连续。
- thinking：轻微歪头、眼神变化，不能频繁大幅摇晃。
- working / reading / writing：手部与道具小幅动作，尽量保持脸和躯干固定。
- waiting：抬手或看向用户，循环应有停顿。
- happy / oops / pet：单次短动作，结束返回当前真实状态。

制作方式优先级：人工分层与补帧 → 有参考约束的图生视频并逐帧修正 → 纯自动生成后严格挑选。每种角色使用同一个角色表、配色、服装和分镜。图生视频只用于离线素材制作；设备端没有视频生成任务。

### C. 分层角色

后续可拆身体、头发、前发、眼睛、手和道具，用 2D 骨骼或受限变换复用动作。分层会增加绘制次数、透明混合和维护复杂度；先在电脑制作烘焙帧，ESP32 播放结果。Live2D 等运行时不能直接假设能在 ESP32 上运行。

## 素材验收标准

统一 320 × 320 输出画布，透明背景，角色脚底锚点目标 (160,308)。原图先按 alpha 包围盒等比缩放，不拉伸、不裁脸、不把头饰挤出画布；同一个角色在所有姿态里的头部尺度应保持在约 ±5% 内，必要时人工校正。留出 8–12 px 边距，尾巴与道具可以适度缩小，但不能改变基本识别特征。

逐帧检查：轮廓闪烁、衣服变化、手指异常、alpha 黑边/白边、重复帧、重心漂移、首尾跳变。半透明边缘以直通 alpha 保存，不重复预乘。RGB565 有色阶损失，要在实际 AMOLED 和目标亮度下看肤色及头发。

原始姿态包没有独立眼睛层。GPT 网页原型已增加独立眼睑和虹膜，其他角色仍按各自的源素材制作。

## 转换管线与包格式

后续工具 `tools/build_asset_pack.py` 按下面规格实现（当前尚未实现）：

源清单 + SHA-256校验 → alpha边界/锚点检查 → 等比归一化 → RGB565与A8转换 → 包索引和CRC → 离线预览 → SD包验收。

初始显示输出采用自定义 BAJ1 容器，避免绑定某一版 LVGL 的内部 bin 文件头。它是 G2 的候选格式，不可直接传给 LVGL 的现成 decoder；需实现受控 reader 并构造对应图像描述或进行混合。

32 字节小端头：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| magic | 4 bytes | ASCII BAJ1 |
| version / header_bytes | u16 / u16 | 1 / 32 |
| width / height | u16 / u16 | 上限 320 / 320 |
| frames / fps | u16 / u16 | 1 为姿态；动画先限制 ≤24 帧、≤12 fps |
| format / flags | u16 / u16 | format=1 为 RGB565_LE + A8 两平面，flags 首版为 0 |
| frame_bytes | u32 | width × height × 3 |
| payload_bytes | u32 | frame_bytes × frames，防整数溢出 |
| payload_crc32 | u32 | 完整帧数据 CRC32 |

每帧先连续 RGB565 小端行数据，再连续 A8 行数据。解码器验证长度、尺寸、帧数、格式与 CRC 后才用；不从不可信包头直接申请任意大小内存。固件资源索引额外记录 SHA-256、作者、许可、动作类型、帧文件路径、锚点、循环和回退项。

首版 48 张姿态若全部归一成此格式，纯像素约 14.06 MiB，放 SD；同时只加载 1–2 张。单个 24 帧动画约 7.03 MiB，全部装入 PSRAM 不可行。可先将屏幕背景固定为黑并预合成 RGB565 来降成本，但这会限制主题光晕和互动叠加，必须在 G2 依据实测决定并修改格式版本。

## 缺资源与热插拔

启动时读索引并验证版本；不存在卡、未挂载、损坏包都进入内置中性图形，不重启循环。切换动作前预取，成功才替换旧图。读取中拔卡立即停止预取并保留已加载图；下一次可用时重新挂载并验证索引。

首版不做边播放边写 SD 的热更新。USB 传状态而非素材；先由电脑拷贝资源卡。以后若实现 OTA / 资源升级，使用临时目录、完整校验和原子切换，不覆盖当前正在播放的包。
