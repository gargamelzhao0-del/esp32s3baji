## 实际发现并处理的问题

1. 当前终端没有激活 IDF，系统 Python 与 IDF venv 不同。工程脚本显式使用已有 venv 和工具目录，不全局安装。
2. 受限执行环境启动 GCC 时出现系统 DLL 重定位错误；在正常 Windows 执行环境检查版本成功。
3. 原中文项目路径让 GCC 无法正确读取 picolibc.specs；UTF-8设置不足以修复。
4. 单独映射盘符后使用 idf.py 仍失败，因为 idf.py 对项目路径做 realpath，还原成中文。
5. 最终方案：临时英文盘符 + 直接 CMake / Ninja 构建。所有文件仍位于用户目录，结束后通过 Unicode API 核对并移除本次映射。此路径已成功构建。
6. Chrome普通命令行窗口截图的窄窗口行为不等同于真实430px viewport；最终用独立浏览器上下文设置430px重新检查并保存截图。

失败尝试的日志保留在忽略的 `build-preparation` / `build-preparation-ascii` 中，最终产物在 `build-preparation-z`。不把失败构建当作源码错误或硬件错误。

## GPT 白龙娘动画

2026-11-19 的 GPT 动画演示在桌面 Chrome 和该浏览器的手机触控模拟中完成验证。鼠标从画面左侧移到右侧，虹膜视线随之转向。揉头、伸手吃糖、接星和回到 Agent 动作都走正常页面入口。互动进度可跨刷新保留，待命时会打盹，触碰后会醒来。打开用量页时角色时钟暂停，开启减少动效后使用静止表情。断开连接后额度显示“—”，本地陪玩仍可用。一次 1.3 秒桌面采样测得约 30 帧/秒。390 像素宽的触控页面通过手势与边缘翻页检查。手势和帧率仍待 ESP32 实屏验证。

首版动作短片为 384 × 384 像素、197 帧。当前预览已更新为下列互动版本。

### 击掌与引萤

- 桌面 Chrome 中分别点击举起的手、另一只手，及等待邀请超时。正确命中只记一次亲密互动，错手或超时均为零次。萤火虫快速经过手心、停在远处、慢下来落手三种情况得到不同结果。两种成功互动之后，再次待命时会用对应的手挥一挥或低头查看。
- 在 360 CSS 像素宽的 Chrome 触屏模拟中，一次连续的长按与拖动完成引萤，再用直接轻点完成击掌。390 像素宽的回归检查覆盖揉头、左右抛星与边缘翻页。两个入口都使用随角色运动的手心位置。
- 左右翼、碰尾巴、连续碰鼻尖、哈欠和醒来伸展均已复核。阅读中开始和退出游戏会收起、恢复书本。等待确认、离开角色页、离线陪玩、系统减少动效、键盘引导和退出均通过检查。
- 桌面 Chrome 一次 1.3 秒采样约 30 帧/秒，角色单帧绘制中位数约 3.1 ms，第 95 百分位约 4.4 ms。记录来自桌面浏览器。触控手感、功耗和帧率需在 ESP32 圆屏上另测。
- 当前短片为 420 × 420 像素、18 秒。重新解码校验了 324 个不同画面、逐帧时长、循环播放及原作者的 XMP 署名。[播放新版动作短片](../design/gpt-pet/gpt-pet-preview.webp)

击掌命中、超时、引萤落手和减少动效也提供了无需浏览器的回归用例。在开发目录运行 `node --test tests/gpt-pet-play.test.cjs`。[互动回归用例](../tests/gpt-pet-play.test.cjs)

### 白龙娘的搬桌、办公和心情表演 · 2026-11-20

在原型的 466 × 466 圆屏内检查了找桌、两次拖动、坐下、按开关、敲键、指屏、主跳、小跳、鼓腮及接糖。桌面使用独立 Chrome 配置，手机使用 360 像素宽的触屏模拟。手机上的小剧场按钮、键盘的首尾分页、减少动效和新 Agent 事件打断均可操作。浏览器无脚本异常。[可玩版本](../design/badge-prototype.html) · [表演调研与实现](10-character-acting.md)

抓取、后拉和刹车的三个采样点上，手心与把手中心的距离均小于 0.01 个逻辑像素。把手全程平移 330 个逻辑像素，折合圆屏约 138 像素。按下开关时验证了掌心对位，敲键时左右掌分别跟随各自的键区。主跳抬升约 97 个逻辑像素，足部离开地面阴影。逐帧检查了搬桌和庆祝期间角色网格的左右边界，246 帧均无角色像素被截在边缘。
