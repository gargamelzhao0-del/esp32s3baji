# 圆屏还能快多少

2026-11-23 在 COM21 同一块微雪 ESP32-S3-Touch-AMOLED-1.75C 上，以 ESP-IDF 5.5.4 和显示驱动提交 `3871ff5` 做了四组 RAM 测试。对这只像素宠物，保留 RGB565，通过局部更新可以让角色、触摸反馈和状态层利用约 59 Hz 的面板节拍。对于确实要改写整个圆面的帧，色深会直接决定能赶上多少次扫描。[串口计时记录](../tests/device/pet_replay/com21-2026-11-23.txt)

## 整圆传输与扫描节拍

板上是双核 240 MHz ESP32-S3R8，配 32 MiB Flash、8 MiB 八线 PSRAM 和 466 × 466 的 CO5300 AMOLED。CO5300 数据手册 §6.4 给出的 QSPI 写周期下限为 20 ns。用本板固件的 SPI2 时钟源和整数分频，在额定范围内的最高档是 40 MHz，四线理论像素载荷为 20 MB/s。驱动覆盖圆面的 182,340 个像素，RGB565 仅发送像素就至少需要 18.234 ms。本次面板 TE 中位周期为 16.987–16.990 ms。增加 CPU 频率、并行渲染或 DMA 队列深度都无法缩短这段线上时间。[微雪板卡资料](https://docs.waveshare.net/ESP32-S3-Touch-AMOLED-1.75C/) · [CO5300 数据手册 §6.4](https://files.waveshare.com/wiki/common/Co5300_Datasheet.pdf#page=107) · [乐鑫 SPI 主机驱动](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-reference/peripherals/spi_master.html)

在相同的整圆范围、17 笔像素 DMA、相同的两个预合成画面之间交替。每次在一个新 TE 上升沿开始。每种色深实测 120 帧。

| 传输格式 | 每帧载荷 | 开始绘制到 DMA 完成 P50 | 在下一 TE 前完成 | 这种调度下的提交频率 |
| --- | ---: | ---: | ---: | ---: |
| RGB565 | 364,680 B | 19.308 ms | 0 / 120 | 29.44 帧/秒 |
| RGB332 | 182,340 B | 10.148 ms | 120 / 120 | 58.86 帧/秒 |

RGB565 的 29.44 来自等下一个新 TE 才起步的策略。连续发送可以高于这个速率，但一次整圆传输仍会跨越扫描周期。RGB332 采用固定的红 3 位、绿 3 位、蓝 2 位。两张源图在可见圆内分别有 208 和 210 种 RGB565 色，量化后均剩 45 种。第一张画面的四种高亮色共占可见圆的 22.56%，全部变成同一个白色。颜色计数取自数字像素，屏幕实际出光未用仪器采样。

## 角色、背景与 Agent 信息

**单角色。** 用当前工作区的八列动作图集，在固定背景中渲染 138 × 132 原画，实板放大到 276 × 264。每个片段截取八个不同姿势，覆盖末帧回首帧。诊断先逐像素检查局刷重建结果，再从绘制起点计到最后一笔 DMA 回收。三种策略各预热 8 帧、测 48 帧。[基准程序与用法](../tests/device/pet_replay/README.md)

| 角色片段 | 整个角色区域 P50 | 单个变化框 P50 | 多个变化区域 P50 | 连续 300 个 TE 中最慢一次从边沿到 DMA 完成 |
| --- | ---: | ---: | ---: | ---: |
| 抱心 | 8.491 ms | 4.886 ms | 3.897 ms | 4.418 ms |
| 近景喷嚏 | 8.487 ms | 8.240 ms | 7.669 ms | 7.844 ms |

两段各处理了连续 300 个边沿，漏过边沿和跨到下一边沿的次数均为零。原动画分别以 16 和 18 帧/秒播放。压力测试每个节拍切一次姿势，产品可以保留原表演速度，把相邻节拍留给凝视、触摸和粒子。测试图集 `heartHug.png` 的 SHA-256 为 `bc18d50ba57f0d43fefb556d55297867240e68612118297154bc713f8a977c27`，`sneeze.png` 为 `9a2265805d76e947f5bb707fee7a91efe318283e365d4c226dae05adb7ea3140`。素材变化后重新构建会使用新图集。

**完整画面。** 通过当前网页的绘制入口生成十幅包含近景角色、视线、天空、纸鹤、像素网格、Agent 状态与额度的画面。逻辑画布为 184 × 184，送屏为 466 × 466。画面提前合成并在板上解压到 PSRAM。板上从确定重绘区域开始计时，包含之后的像素读取和 DMA 回收。每个转场预热后测八次，下表是各转场的 P50，第一行给出七次转场各自 P50 的范围。

| 画面变化 | 预先记录变化区域 | 在板上比较 184 × 184 的 8 × 8 像素块后发送 | 在板上比较两张 466 × 466 图后发送单框 |
| --- | ---: | ---: | ---: |
| 连续七个抱心、视线与环境动作转场 | 4.744–11.436 ms | 9.844–15.437 ms | 20.008–24.998 ms |
| 姿势保持，更新 Agent 状态、额度、上下文及环境 | 2.889 ms | 7.778 ms | 31.315 ms |
| 日景转夜景，保持姿势 | 8.801 ms | 13.366 ms | 23.809 ms |
| 夜景回日景，同时切换姿势与状态 | 16.503 ms | 18.773 ms | 25.151 ms |

同一批画面每次完整重传的 P50 为 19.305–19.310 ms。离线变化表在主机逐像素验算；实时逻辑块方案在实板上用窗口回填独立的 466 × 466 帧缓冲，十次结果均与目标图一致。完整合成帧的计时未包含实时生成角色、背景、文字和触摸输入的开销。最重转场的离线方案最大耗时 16.524 ms，距下一次扫描只剩约 0.47 ms。

## PSRAM 与 CPU 余量

对相同的 364,680 字节预生成画面，各方案各负载采样 40 次。表中 CPU 时间为占用显示任务所在核的平均时间，传输时长为从开始到最后一笔 DMA 回收的中位数。并发条件为另一核连续在 PSRAM 中复制数据。

| 像素来源和传输方式 | 单独运行耗时 / 每帧 CPU 时间 | 另一核访问 PSRAM 时耗时 / 每帧 CPU 时间 |
| --- | ---: | ---: |
| PSRAM 复制到两块内部 DMA 缓冲 | 19.329 / 7.236 ms | 19.859 / 15.465 ms |
| DMA 直接读取已对齐的 PSRAM 条带 | 19.598 / 1.378 ms | 19.813 / 1.593 ms |

直接读取在两组共 80 帧中未观察到 DMA 欠载，源数据校验通过。适合已生成、正确对齐、在 DMA 完成前保持不变的素材。预生成和缓存维护的成本、无线及音频同开时长时间运行的稳定性仍需在应用集成后计量。当前主工程的显示驱动使用两块内部 DMA 缓冲。

## 对电子吧唧的实施取舍

1. 主画面保留 RGB565。为姿势帧导出变化区域，动态五官、触点、粒子和 HUD 在状态改变时登记旧、新边界，绘制时重合成边界内的全部可见图层。静止的背景和网格可复用。
2. GPIO13 的 TE 驱动显示节拍。角色按动作原速播放，触摸和凝视可在下一节拍更新。大范围换景单独安排预算，优先保证触摸响应。实时全屏逐像素比较在这次工作负载中耗时最高。
3. 预生成素材可优先验证 PSRAM 直送，以便释放 CPU 给互动合成。大面积连续更新且能为 3-3-2 色域专门配色的场景，可单独评估 RGB332。当前角色高光和背景用 RGB565 更接近原画。

这些实验以 TE 中断和 DMA 回收计时。真实触摸到出光的延迟、光学撕裂和连续运行的整机帧率仍需在集成版测量。测试均通过 RAM 镜像运行。结束后已核对启动程序、分区表、factory 分区及 Flash 末扇区的前后摘要，并确认 MotoNav 0.3.18 / NAV3 从 Flash 启动。
