# AI 电子吧唧：产品与需求基线

版本：准备版 0.1；日期：2026-11-18。工程根目录：`D:\esp32电子吧唧\esp32s3baji`。

## 产品要解决什么

用户正在电脑上让 Agent 工作，圆屏上的角色能让人一眼知道：谁在工作、用什么模型、正在做什么、是否需要我介入、额度还剩多少。轻触角色能产生回应；切换客户端时能感到角色和氛围发生变化。电脑合盖、串口掉线、数据读不到时，应如实显示未知或离线。

首版是一枚与电脑联动的角色徽章，同时也是桌面状态伴侣。ESP32 不运行大模型、不分析提示词、不从电脑实时接收视频。角色动效在设备本地播放。

## 五个维度，独立建模

| 维度 | 来源 | 决定的内容 |
| --- | --- | --- |
| 客户端 client | 适配器身份 | Codex、Claude Code 等界面主题 |
| 模型 provider / model_id | 实际运行事件 | GPT、Claude、DeepSeek、Gemini 基础角色 |
| 模型变体 variant | 已验证的型号映射 | Opus / Sonnet 徽记，后续可加服装；不凭客户端猜型号 |
| 会话状态 phase / activity | 生命周期与工具事件 | 姿态、状态文案、提示动效 |
| 数值与设备状态 | 各自可靠来源 | 订阅额度、上下文、Token、电池和连接 |

例如 Claude Code 连接 DeepSeek 时，保留 Claude 的暖色界面，但角色是鲸鱼娘。Opus 首版采用 Claude 角色加 Opus 标签，尚无单独验证可用的 Opus 连续动画素材。模型未知时显示中性保底角色和“模型未知”。

## 首版功能边界

| 编号 | 功能 | 首版完成标准 |
| --- | --- | --- |
| R01 | 客户端主题 | Codex、Claude Code、默认主题分别可辨认 |
| R02 | 模型角色 | GPT / Claude 实际接入；DeepSeek / Gemini 可由真实元数据或演示回放展示 |
| R03 | 工作同步 | idle / working / tool / waiting / ended / error / limited 七种会话状态；离线为独立连接状态 |
| R04 | 使用信息 | 有来源的额度桶、上下文；Token 详情；未知、估算、过期明确标识 |
| R05 | 多会话 | 手动固定优先；可识别的前台会话其次；同客户端最近活动会话兜底 |
| R06 | 本地互动 | 点角色回应、划动翻页、长按设置、会话固定与电脑端定位 |
| R07 | 通信恢复 | USB 原生串口、帧校验、完整快照、自动恢复；不串日志、不误显示旧会话 |
| R08 | 素材与渲染 | 角色姿态、轻量动效、SD 包校验和缺失回退 |
| R09 | 电源 | 亮度、闲置降亮、USB / 电池区分；电池数据必须由 PMIC 验证 |
| R10 | 可维护性 | 固定依赖、离线回放、错误计数、验收记录、恢复路径 |

普通 ChatGPT / Claude 网页聊天不等同于 Codex / Claude Code。若目标界面没有可用的正式事件接口，只能显示客户端在前台及手动选择的角色，不能声称已经获得真实执行状态。普通聊天接入单独排期。

第二阶段：Wi-Fi 配对、抬腕唤醒、更多适配器、声音、真正的帧动画。语音聊天、云端生成视频、复杂三维、触屏批准命令、震动硬件不进入首版。板载没有已确认的震动马达，不在方案里假设存在。

## 信息可信度

来源状态使用 reported / estimated / unknown；新鲜度由 age_ms 与 ttl_ms 独立计算。estimated 不可去掉“约”或“估算”标记。断联后的数字只可在详情页作为带时间说明的历史数据，主屏改为 —。

“本轮结束”只表示 Agent 停止了本轮；只有明确成功来源才播放成功动画。一般工具失败先记局部错误，允许 Agent 继续恢复，不能将整个任务立即判失败。“思考”是工作状态的视觉表达，不代表读取模型内部推理。
